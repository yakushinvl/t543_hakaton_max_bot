# Мини-приложение «Флюгер» для мессенджера MAX

Мини-приложение и чат-бот для мессенджера MAX (max.ru). Проект предназначен для поиска городских событий, получения персональных рекомендаций по интересам и возрасту, просмотра мероприятий на карте, создания пользовательских встреч и общения во встроенных чатах.

- Чат-бот в MAX: https://max.ru/t543_hakaton_max_bot

---

## Назначение решения

Сервис закрывает три основные задачи:
1. Подбор мероприятий: рекомендательный алгоритм сопоставляет возраст, пол и выбранные интересы пользователя с событиями города, рассчитывает процент соответствия и выводит причину рекомендации.
2. Карта событий: отображение площадок и мероприятий на векторной карте с кластеризацией меток.
3. Совместные активности: создание публичных и приватных встреч, генерация ссылок-приглашений для друзей в мессенджере MAX, координация в чате мероприятия и запись на событие.

---

## Основной пользовательский сценарий

1. Пользователь находит бота @t543_hakaton_max_bot в мессенджере MAX и отправляет команду /start.
2. Бот присылает сообщение с кнопкой запуска мини-приложения.
3. При первом входе открывается онбординг:
   - Приложение читает имя пользователя из профиля MAX с возможностью ручного редактирования.
   - Пользователь указывает возрастную группу (6-8, 9-11, 12-14, 15-17, 18-24, 25-34, 35-49, 50-59, 60+).
   - Выбирает пол (подписи адаптируются под выбранный возраст).
   - Выбирает интересующие тематики в сетке категорий.
4. На основе ответов формируется персональная выдача:
   - Вкладка «Флюгер»: выдача рекомендуемых событий с расчетом процента совпадения и кнопкой случайной ротации.
   - Вкладка «События»: общий каталог с поиском, фильтрами по датам и категориям, а также личные списки («Сохранённые», «Хочу пойти»).
   - Вкладка «Карта»: просмотр событий по локациям с группировкой в кластеры при изменении масштаба.
   - Вкладка «Социалка»: создание своей встречи, получение инвайт-ссылки формата startapp для отправки контактам в MAX, чат участников.
   - Вкладка «Профиль»: просмотр сохраненных данных и настройка контактов для быстрой записи на события.

## Состав и архитектура решения

Проект представляет собой единый сервис, объединяющий клиентскую и серверную части:

- Клиент (frontend):
  - React 19, TypeScript, Vite.
  - Картография: MapLibre GL и библиотека кластеризации Supercluster.
  - Иконки: Lucide React.
  - Интеграция с платформой через MAX WebApp SDK (st.max.ru/js/max-web-app.js).
  - Локальное кэширование состояния в LocalStorage.

- Сервер (backend):
  - Node.js 20, Express, TypeScript (запуск через tsx).
  - REST API: выдача событий, аналитика рекомендаций, управление чатами и встречами, healthcheck.
  - Валидация подписи initData мессенджера MAX по HMAC-SHA256.
  - Провайдеры данных: интеграция с KudaGo API, локальными городскими источниками и встроенным генератором резервных событий.
  - Кэширование внешних запросов в оперативной памяти на 45 минут.
  - Проксирование изображений (/kg-media/*) с простановкой CORS и Cache-Control.

- Чат-бот:
  - Библиотека @maxhub/max-bot-api.
  - Работает в том же процессе, что и бэкенд, в режиме polling (также есть эндпоинт для webhook).
  - Обрабатывает команды /start, запуск по реферальным ссылкам и отправляет кнопки открытия мини-приложения.

- Хранение данных:
  - Локальная база данных на JSON-файле (server/data/db.json).

## Запуск одной командой через Docker

Сборка и запуск всех компонентов выполняются одной командой:

```bash
docker compose up -d --build
```

(или `docker-compose up -d --build` для старых версий Compose).

Сборка многоэтапная (multi-stage на Alpine Linux), занимает менее 1 минуты. Приложение становится доступно по адресу http://localhost:3001.

---

## Параметры и переменные окружения

Настройка производится через файл `.env`. Пример заполнения находится в `.env.example`:

```bash
cp .env.example .env
```

Переменные:
- `PORT` — сетевой порт HTTP-сервера (по умолчанию: 3001).
- `BOT_TOKEN` — токен бота от @BotFather в MAX. Если не указан, сервер и веб-приложение продолжают работать, а бот переходит в режим ожидания.
- `BOT_NAME` — имя бота в мессенджере MAX (по умолчанию: t543_hakaton_max_bot).
- `OPENAI_API_KEY` — опциональный ключ API для внешнего LLM-анализа. Если не задан, расчет рекомендаций выполняет локальный семантический модуль.

---

## Используемые порты

- `3001` (TCP) — единый HTTP-порт приложения. Через него отдается статический фронтенд, обрабатываются запросы к API (/api/*), отдаются кэшированные изображения (/kg-media/*) и принимаются проверки доступности (/api/health).

## Внешние сервисы и интеграции

1. Мессенджер MAX:
   - Служит платформой запуска мини-приложения и источником авторизации пользователей.
   - Для полноценной работы с чат-ботом требуется интернет и доступ к серверам MAX.
   - Действующая версия продукта уже настроена и доступна в мессенджере по ссылке https://max.ru/t543_hakaton_max_bot.
   - В локальном Docker веб-интерфейс открывается в обычном браузере со встроенными заглушками методов WebApp.

2. API KudaGo (kudago.com):
   - Используется для загрузки актуальных событий.
   - Требует исходящего HTTPS-доступа. При отсутствии связи бэкенд автоматически переключается на встроенную резервную базу событий.

3. Картографические тайлы OpenStreetMap:
   - Используются для отрисовки карты MapLibre GL. Требуют исходящего HTTPS-соединения.

## Описание работы с данными

- Данные приложения (пользовательские встречи, чаты, профили и записи) сохраняются на сервере в `server/data/db.json`.
- В Docker Compose директория `server/data` вынесена в именованный том `app_data`, поэтому данные не стираются при перезапуске контейнера.
- На клиенте используется синхронизация через LocalStorage, что ускоряет повторные открытия интерфейса.

---

## Порядок работы с тестовыми данными

- При первом запуске файл базы данных создается автоматически.
- В коде провайдеров уже заложены готовые тестовые мероприятия для городов (Москва, Санкт-Петербург, Казань), поэтому ручное наполнение базы перед проверкой не требуется.
- Для полного сброса базы данных к начальному состоянию:
  ```bash
  docker compose down -v
  docker compose up -d
  ```

## Пошаговый сценарий проверки

1. Запустить контейнер:
   ```bash
   docker compose up -d --build
   ```

2. Проверить статус контейнера:
   ```bash
   docker compose ps
   ```

3. Проверить ответ проверки работоспособности:
   ```bash
   curl http://localhost:3001/api/health
   ```
   Сервер должен вернуть HTTP 200 со статусом `ok`.

4. Проверить получение списка событий через API:
   ```bash
   curl "http://localhost:3001/api/events?city=kzn"
   ```
   Должен вернуться JSON-массив событий.

5. Проверить веб-интерфейс в браузере:
   - Открыть http://localhost:3001.
   - Пройти онбординг (ввод имени, выбор возраста, пола и интересов).
   - На вкладке «Флюгер» нажать кнопку запуска рекомендаций.
   - На вкладке «События» проверить работу фильтров и карточки события.
   - На вкладке «Карта» убедиться в наличии меток и кластеров.
   - На вкладке «Социалка» создать тестовую встречу и отправить сообщение в чат.

6. Проверить работу в мессенджере MAX:
   - Открыть диалог с ботом https://max.ru/t543_hakaton_max_bot.
   - Отправить `/start` и нажать кнопку запуска мини-приложения.

## Известные ограничения

1. Вебхуки платформы MAX требуют публичного HTTPS-адреса. В локальном Docker бот работает через polling.
2. Тактильный отклик (Haptic Feedback) поддерживается только в мобильном приложении MAX на смартфонах. При открытии в браузере на ПК вызовы метода безопасно игнорируются.
3. При недоступности внешнего API KudaGo выдаются встроенные события-заглушки.
